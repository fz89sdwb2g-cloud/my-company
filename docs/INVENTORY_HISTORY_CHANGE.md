# Історія залишків і відновлення оновлення магазинів

Пропозиція від 23.11.2026. Робочу програму не змінено; застосувати після погодження власника.

## Зміни
- Кнопка «Оновити показані дані» повідомляє про завантаження, успіх, помилку та потребу входу. Вона перечитує хмару, не запускає КУСТ.
- Окрема «Історія товарних залишків»: останні 120 успішних знімків двох локацій із датою, сумою, кількістю товарних позицій і мінусових позицій. Усі джерельні значення вставляються через textContent.
- Нове приватне сховище історії: authenticated читає лише свої рядки, записує лише сервер. Тригер зберігає знімок атомарно з основним записом, повтор того самого snapshot_id не створює дубля. Поточні перевірені знімки стають початковими, історія минулих днів не вигадується.
- З cust-stores-sync вилучений невикористаний GET /locations. За журналом остання невдала спроба повертала CUST_LOCATIONS_HTTP_ERROR, upstream_status 401. GET /inventory вже має поновлення токена після 401; перевірки класифікації, валюти, кількості, вартості й пагінації збережено. Причина недійсності токена (зокрема можливий вплив одночасних входів) не доведена; видалення зайвого запиту усуває підтверджене місце збою, але реальний успішний імпорт після деплою ще необхідно перевірити.

## Збереження
Приватна копія company_data й cust_inventory_snapshots збережена поза GitHub. Це копія хмари, а не незбережених localStorage іншого пристрою. Формат company_data та ключі localStorage не змінюються. Старий код функції доступний у її попередній версії та git. Не додавати backup JSON у репозиторій.

node --check для UI і серверної функції: успіх.
node tests/test-inventory-history.cjs: успіх (оновлення без /locations; токен 401 з повторним входом; відмова при іншій валюті; повідомлення кнопки; історія; очищення після виходу; помилка читання).
Це ізольовані тести з вигаданими даними, не перевірка справжнього входу власника.
Раніше npm test на main падав через неповну auth-заглушку; цей PR її не змінює. Міграція ще не застосована й не перевірена на живій базі.

## Порядок випуску після погодження
1. Звірити свіжість приватної копії.
2. Застосувати supabase/inventory-history.sql; перевірити RLS та початкові рядки без виводу приватних значень.
3. Розгорнути supabase/functions/cust-stores-sync/index.ts зі збереженням чинної авторизації та verify_jwt=false, як у поточній функції.
4. Один авторизований запуск імпорту; підтвердити нову дату, відсутність помилки та рівно один запис історії. Повтор із тим самим знімком не має додати запис.
5. Злити PR, дочекатися Pages, перевірити кнопки після входу власника, анонімну відмову й відмову для чужого користувача.
