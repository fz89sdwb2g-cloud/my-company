# КУСТ → «Моя компанія»: борги клієнтів
Статус: потрібне розширення API КУСТ; поточна версія передає лише locations, receipts, inventory. Цей документ є пропозицією контракту, а не описом уже наявного ендпойнта.

## Результат
Показати всі непогашені борги клієнтів і прострочену частину, з датою актуальності. Борги постачальникам, аванси й переплати показувати окремо. Відсутність даних не означає нуль.

## Джерело і визначення залишку
- Використати той самий розрахунок, що у звіті боргів робочої КУСТ, станом на узгоджений знімок.
- Врахувати початкові борги, проведені продажі, часткові й повні погашення, повернення та коригування; включити борги, що виникли до поточного місяця.
- Не виводити борг із загальної виручки чи касового приходу. Касовий прихід може містити погашення, аванси й перекази.
- У старій схемі є mcheck.debt, chkpay, cash, ordcash, ordercash та ord.dbt. Розробник має підтвердити їхню семантику й відповідність звіту; самі назви полів не є достатньою підставою для розрахунку.

## Пропонований GET /api/v1/receivables
Зберегти чинний HTTPS/Bearer-вхід; надати окремий дозвіл читання боргів. Точний шлях і контракт погодити перед запуском.

Поля рядка:
- debt_id — стабільний непрозорий код документа/боргу, унікальний у компанії;
- customer_code — стабільний знеособлений код без можливості встановити особу з відповіді;
- location_id — точка обліку;
- currency — UAH;
- outstanding_amount — поточний непогашений додатний залишок, десятковий рядок із двома знаками;
- agreed_due_date — погоджена дата оплати YYYY-MM-DD або null;
- handover_date — дата передачі товару YYYY-MM-DD або null.

За потреби передавати document_amount, paid_amount та adjustment_amount тільки з погодженою формулою їх зв’язку із залишком. Клієнтські переплати не віднімати від боргів інших клієнтів: повертати їх окремим підсумком.

Без ПІБ, телефонів, адрес, email, платіжних реквізитів, приміток або токенів у даних і журналах.

Метадані: snapshot_id, data_as_of, next_cursor, complete. Усі сторінки одного знімка узгоджені. limit до 500; фільтр location_id опційний, без нього — всі доступні точки. Надати контрольний підсумок total_outstanding для звірки повної вибірки. Порожній підтверджений знімок: 200 і data: []; недоступне джерело: 503.

## Прострочення
- Погоджена дата має пріоритет.
- За її відсутності строк — 14 календарних днів після передачі товару.
- Прострочення починається наступного дня після строку, за Europe/Kyiv.
- Без обох дат борг входить до загальної суми, а його строк показується як невідомий. Його не зараховувати автоматично до простроченого.
- Сума прострочених + непрострочених + боргів із невідомим строком має дорівнювати загальному непогашеному залишку.

## Перевірка перед заповненням панелі
1. Звірити весь залишок зі звітом КУСТ на однаковий час і за всіма локаціями.
2. Перевірити приклади часткової/повної оплати, старого боргу, повернення, переплати й відсутньої дати.
3. Перечитати всі сторінки іншим розміром сторінки: суми та кількість унікальних debt_id мають збігтися.
4. Тільки після звірки зберігати новий знімок. При збої зберігати попередню версію з попередженням про актуальність.
5. Оновлювати щодня о 07:00 за Києвом. При кожному запуску отримувати новий токін; чинний токін КУСТ живе одну годину.
